# vLLM на CPU в Minikube

Qwen2.5-0.5B-Instruct с HTTP API, PVC для весов и отдельным загрузчиком. После первого скачивания Pod запускается с локальной моделью при запрещённой исходящей сети. Сервер и загрузчик работают с UID 10001.

Выбраны vLLM 0.27.0+cpu и float32. На тестовом i5-7300HQ есть AVX2, но нет AVX-512; эта комбинация проверена настоящими запросами. Revision модели: `7ae557604adf67be50417f59c2c2f167def9a775`.

## Запуск

Нужны Ubuntu 24.04 с systemd, Docker Engine, 4 CPU, минимум 8 ГиБ свободной RAM и 40 ГиБ места на диске. Проверено в WSL2. Из корня проекта:

```bash
sudo bash scripts/setup-kubernetes.sh
sudo python3 scripts/ask.py
```

Первый скрипт установит Minikube 1.39.0 и kubectl 1.37.0, соберёт два образа, загрузит модель и проверит её повторный запуск без сети. Второй предложит ввести вопрос. На этом CPU подготовка сервера и первый запрос занимают несколько минут; последующие запросы заметно быстрее.

Для первой установки нужен интернет до реестров образов, GitHub, dl.k8s.io и Hugging Face. В WSL с VPN могут потребоваться настройки из [инструкции развёртывания](docs/deployment.md). Терминал Ubuntu нужно оставить открытым.

Модель публичная, поэтому HF Secret содержит пустую строку. Для gated-доступа предусмотрен `HF_TOKEN_FILE` — путь к файлу с токеном. API-ключ генерируется при установке и передаётся через Secret; `ask.py` использует его внутри клиентского Pod.

## Устройство

```text
initContainer → файлы модели в PVC → vLLM → Service cpu-llm:8000
                      ↑                  ↑
                 HF Secret       ConfigMap + API Secret
```

`Dockerfile` фиксирует CPU-образ по digest, а `requirements.txt` — все 155 Python-пакетов. Сборка проверяет их версии и `pip check`. В `downloader/` используется только стандартная библиотека Python; каждый файл сверяется по размеру и SHA-256.

Параметры находятся в `config/server.json`: контекст 1024 токена, максимум две активные последовательности. Сервер ограничен 3 CPU и 7 ГиБ RAM. Одна реплика и `Recreate` позволяют обновлять его без второй копии модели в памяти.

Журнал содержит метаданные обращений. Сырой вывод vLLM закрыт, чтобы текст ошибки тоже не раскрыл вопрос или ответ. Это решение уменьшает подробность диагностики; устройство и ограничения описаны в [logging.md](docs/logging.md).

## Проверки и замеры

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -q
sudo python3 scripts/verify_release.py
sudo python3 scripts/run_benchmark.py --label run-1 --requests 8
```

Для `verify_release.py` нужен уже запущенный сервис. Он сверяет исходники с образом, проверяет API, SSE, логи и блокировку сети. Для бенчмарка используется отдельный клиент с лимитами 1 CPU / 256 МиБ. [Методика и повторные прогоны](docs/benchmark.md).

Ниже — часть опыта с двумя клиентами: по 8 запросов, около 64 или 592 входных токенов и ровно 32 выходных. Всего в сравнении двух конфигураций выполнено 96 запросов, ошибок нет.

| Вход | max_num_seqs | TTFT, медиана, с | Latency, медиана, с | Выходные токены/с |
| --- | --- | --- | --- | --- |
| Короткий | 1 | 5.789 | 10.691 | 5.67 |
| Короткий | 2 | 1.125 | 10.641 | 5.77 |
| Длинный | 1 | 11.714 | 16.710 | 3.80 |
| Длинный | 2 | 7.022 | 18.197 | 3.35 |

Оставлен лимит 2: при параллельной нагрузке первый текст приходил раньше. Для выбора по общей скорости нужны повторы — между прогонами изменился и контроль с одним клиентом.
